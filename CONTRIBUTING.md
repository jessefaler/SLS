# Contributing to SLS

Thank you for your interest in contributing to **SLS**! This document outlines how to submit bug reports, feature suggestions, and code changes.

## Getting Started

The easiest way to get started is to ask for help in our [Discord server](https://discord.com/invite/BrH8GtyGSh).

## How to Contribute

### Reporting Bugs
1. Check the [issue tracker](https://github.com/jessefaler/SLS/issues) to see if your bug has already been reported.
2. If not, open a new issue using any template provided.
3. Include clear steps to reproduce the problem, and add screenshots, logs, or small code snippets when possible.

### Suggesting Features
1. Open a new issue on the issue tracker.
2. Describe the feature clearly: the problem it solves, how it might work, and any tradeoffs or implementation ideas.

### Contributing Code
1. **Fork and Clone** – Fork the repository on GitHub, then clone your fork locally.
2. **Branch** – Create a branch for your work (e.g., `fix/...` or `feature/...`) instead of committing directly to `main`.
3. **Tooling** – SLS uses Go and Java. Install the appropriate Go toolchain and JDK, and run the usual build/test commands before opening a PR.
4. **Submit** – Push your branch to your fork and open a pull request against the upstream repository. Summarize what changed, why, and link any related issues.

Pull requests are reviewed according to this `CONTRIBUTING.md` and the **Individual Contributor License Agreement (ICLA)** where applicable.
